This page lists the commands actually used on this Raspberry Pi 5 by the Athéna layer, the proof manifests and the daily checks. Each one was run on 22 November 2026 on the machine hosting the site; the output reproduced here is what was obtained, unedited.

The content is split into 19 fiches, one per command (F01 to F19). Each fiche answers three questions: the command that was run, what it checks, and the trap it avoids. Fiches are grouped by theme; the numbering is stable and serves as an anchor.

It complements Before plugging in a sensor (power and buses) and Proof manifest format (how a command becomes a proof). Here the arsenal itself is described.

1. Identity, not architecture alone

F01 — tr -d '\0'

$ tr -d '\0' </proc/device-tree/model
Raspberry Pi 5 Model B Rev 1.1

Checks : the exact board model, revision 1.1.

Trap avoided : /proc/cpuinfo gives the processor (BCM2712) but not the board revision. cat /proc/device-tree/model ends with a NUL byte and no newline, so it sticks to the prompt ; tr -d '\0' yields a clean line.

F02 — uname -srm

$ uname -srm
Linux 6.18.50+rpt-rpi-2712 aarch64

Checks : the kernel and the arm64 architecture.

Trap avoided : uname -m alone gives aarch64 and says nothing about the kernel ; the +rpt-rpi-2712 suffix confirms a Raspberry Pi kernel.

F03 — python3 --version

$ python3 --version
Python 3.13.5

Checks : the interpreter that runs the proof scripts.

Trap avoided : python --version may point at another interpreter — manifests explicitly use python3.

2. GPIO : the right controller, the right number

F04 — gpiodetect

$ gpiodetect
gpiochip0 [pinctrl-rp1] (54 lines)
gpiochip10 [gpio-brcmstb@107d508500] (32 lines)
gpiochip11 [gpio-brcmstb@107d517c00] (15 lines)
gpiochip12 [gpio-brcmstb@107d517c20] (6 lines)
gpiochip13 [gpio-brcmstb@107d508520] (4 lines)

Checks : the header is gpiochip0, driver pinctrl-rp1 — the Pi 5 southbridge RP1.

Trap avoided : gpiodetect also lists four BRCMSTB chips ; the mistake would be to take “the first one” or gpiochip10. RPi.GPIO imports on this machine, but the layer uses lgpio/gpiod and BCM numbers.

F05 — gpioinfo | grep onewire

$ gpioinfo | grep onewire
        line   4: "GPIO4"   output drive=open-drain consumer="onewire@0"

Checks : BCM4 is reserved for the 1-Wire bus.

Trap avoided : the line shows as output because it is being driven at that instant of the 1-Wire cycle ; pinctrl get 4 may show input a microsecond later. That is not a conflict. Physical pin 7 is BCM4: reason in BCM, never in pin number.

3. Heat and throttling

F06 — vcgencmd measure_temp && vcgencmd get_throttled

$ vcgencmd measure_temp && vcgencmd get_throttled
temp=42.8'C
throttled=0x0

Checks : SoC temperature and power/thermal state.

Trap avoided : reading only the temperature. throttled=0x0 is proof that no throttling is active or has occurred ; a non-zero code splits into current and past bits. The && guarantees both readings come from the same instant ; with ; they could be separated. Thermal throttle reference : about 80 °C — 42.8 °C measured here.

4. Buses and sensors

F07 — ls /dev/i2c-* /dev/spidev* 2>/dev/null

$ ls /dev/i2c-* /dev/spidev* 2>/dev/null
/dev/spidev0.0
/dev/spidev0.1
(return code 2)

Checks : two SPI devices present, no I2C device (i2c_arm=on in the config but the i2c-dev module is not loaded at boot, so no /dev/i2c-1).

Trap avoided : 2>/dev/null hides the error message but code 2 remains — that is proof of absence, not a command failure. Adding || true would turn the absence into a success : never do that in a manifest.

F08 — cat /sys/bus/w1/devices/w1_bus_master1/w1_master_slaves

$ cat /sys/bus/w1/devices/w1_bus_master1/w1_master_slaves
00-666800000000
00-e66800000000

Checks : the 1-Wire bus enumerates two ROMs of family 0x00.

Trap avoided : those ROMs change on every read and have no w1_slave file — they are ghosts from a floating bus, not sensors. A real sensor gives a stable 28-… ROM and crc=… YES in w1_slave. The list recorded here differs from the guide’s : expected on a bus with no sensor.

5. Services and timers

F09 — systemctl --failed --no-pager

$ systemctl --failed --no-pager
  UNIT LOAD ACTIVE SUB DESCRIPTION

0 loaded units listed.

Checks : no systemd unit in failed state.

Trap avoided : --no-pager is essential in cron, otherwise the pager waits for a keypress. --failed does not replace is-active : a merely inactive unit is not a failure.

F10 — systemctl list-timers 'athena-*' --no-pager

$ systemctl list-timers 'athena-*' --no-pager
NEXT                            LEFT LAST                              PASSED UNIT
Sun 2026-11-22 19:49:48 EST      30s Sun 2026-11-22 19:48:48 EST      29s ago athena-health.timer
Sun 2026-11-22 19:50:33 EST 1min 15s Sun 2026-11-22 17:50:33 EST 1h 58min ago athena-git-sync.timer
Sun 2026-11-22 19:51:00 EST 1min 42s Sun 2026-11-22 19:48:01 EST 1min 15s ago athena-flux.timer
Sun 2026-11-22 19:54:33 EST     5min Sun 2026-11-22 19:39:33 EST      9min ago athena-gardien.timer
Mon 2026-11-23 03:17:00 EST       7h Sun 2026-11-22 03:17:11 EST      16h ago athena-vault-backup.timer
(excerpt — 7 timers in total, return code 0 without a pipe)

Checks : seven athena-* timers loaded and their next run.

Trap avoided : measured today, systemctl list-timers … | head -8 returns code 141 (SIGPIPE) while the timers are fine. A head must never supply a proof’s verdict : truncate the output afterwards, not the pipe.

F11 — systemctl is-active …

$ systemctl is-active athena-health.timer athena-health-web.service athena-vault-backup.timer athena-git-sync.timer
active
active
active
active

Checks : the four units queried are active at the time of the reading.

Trap avoided : is-active describes the current state, is-enabled boot-time enablement. Code 3 means “inactive”, not a system error.

6. Local network

F12 — ss -ltnp | grep -E ':8080|:8081'

$ ss -ltnp | grep -E ':8080|:8081'
LISTEN 0  5  127.0.0.1:8081  0.0.0.0:*  users:(("python3",pid=240333,fd=3))
LISTEN 0  50 [::ffff:127.0.0.1]:8080  *:* users:(("signal-cli",pid=1157,fd=16))

Checks : listening ports and their processes, both on loopback.

Trap avoided : an open port does not prove an HTTP reply ; follow up with fiche F13. -p shows the PID only if the user has permission.

F13 — curl -s -o /dev/null -w '%{http_code}\n' 127.0.0.1:8081/

$ curl -s -o /dev/null -w '%{http_code}\n' 127.0.0.1:8081/
200

Checks : the local homepage replies.

Trap avoided : -s and -o /dev/null hide the body and error messages ; a 200 alone proves the reply, not the content. IPv6 was broken on this Pi (dual stack ~24 s) ; /etc/gai.conf sets precedence ::ffff:0:0/96 100 to prefer IPv4. Elsewhere, force curl -4.

7. Health and data

F14 — python3 sys/health_status.py

$ python3 sys/health_status.py
Dernier échantillon : 2026-11-22T19:48:48-05:00
  température   42.8 °C   (24 h : min 38.9 / moy 41.84 / max 62.6)
  throttled    0x0
  tension cœur  0.7638 V
  uptime        76.2 h   charge 0.21
  disque        16.6 %   (24 h max 16.6 %)
  unités en échec 0   wlan -64.0 dBm   ntp oui
  échantillons 24 h : 1370   événements throttle : 0

Checks : consolidated reading of data/health.db, systemd units, temperature and network.

Trap avoided : the script reads the database, it does not rewrite it. The alerts at the end of the output are historical (18 and 21 November) : do not confuse them with the current state, which is 0 unité en échec.

F15 — select count(*) from samples

select count(*) from samples

Checks : the number of recorded samples, delegated to the database rather than typed by hand.

Trap avoided : the engine opens the database with URI file:…?mode=ro — read-only, the manifest cannot modify what it measures. count(*) returns 0 for an empty table ; that is not the same as a missing database.

8. Git and backup

F16 — git bundle verify state/vault.bundle

$ git bundle verify state/vault.bundle
The bundle contains these 2 refs:
360336371e5fc79e55bbf95cb517f4f7d82fdad0 refs/heads/main
360336371e5fc79e55bbf95cb517f4f7d82fdad0 HEAD
The bundle records a complete history.
The bundle uses this hash algorithm: sha1

Checks : the vault bundle is readable, complete and covers the history.

Trap avoided : verify does not prove the repository actually restores. The guide’s proof chains git clone of the bundle, git fsck --full and sha256sum of a known file.

F17 — git ls-files | grep -E 'secrets/|\.env|\.seed'

$ git ls-files | grep -E 'secrets/|\.env|\.seed' || echo 'aucun secret versionné'
aucun secret versionné

Checks : no sensitive file is in the git index.

Trap avoided : without || echo, grep returns code 1 when nothing matches (measured : rc=1) — a “failure” that is good news. The content of a secret must never be displayed ; only its absence is established.

F18 — git log -1 --format='%h %ad %s' --date=short

$ git log -1 --format='%h %ad %s' --date=short
3d945a3 2026-11-22 sauvegarde auto 2026-11-22 18:55

Checks : latest commit, short date and subject.

Trap avoided : without --date=short, %ad produces a verbose, locale-dependent date, hence not reproducible from one machine to another.

9. Backlog

F19 — python3 sys/backlog.py etat

$ python3 sys/backlog.py etat
backlog : 129 tâches — {'fait': 42, 'bloqué': 3, 'prêt': 84}
reste : 2495 min (41.6 h)
prochaine : T30 — Référentiel de commandes

Checks : the real state read from state/backlog/taches.json, and the next task returned by python3 sys/backlog.py suivante (here T30).

Trap avoided : etat gives the counters, suivante gives the task to run. A bloquée task is not a faite task. Do not recompute the plan by hand : state/plan.md is regenerated from the JSON by script.

10. Writing rules — six traps recapitulated

  1. Never correct a failure with || true : the “OK” verdict loses all meaning.
  2. 2>/dev/null hides the message, not the return code : let the code appear.
  3. Never make a | head a proof : SIGPIPE 141 is not a service failure.
  4. On Pi 5, RPi.GPIO imports but the layer uses lgpio/gpiod ; gpiodetect lists five chips, the header is gpiochip0.
  5. Reason in BCM, not in physical pin number.
  6. Do not echo a number : delegate the measurement to a command or to a SQL counter in mode=ro.

The full contract is in Proof manifest format.

Limits

No voltage measurement with a multimeter and no resistance measurement with an ohmmeter were made : no instrument is connected. No family 0x28 sensor is plugged in : the crc=… YES line was not observed here. The output above is a snapshot of 22 November 2026 : 1-Wire ROMs, temperature, counters and PIDs change from one run to the next. A command verified here does not guarantee the same value tomorrow — only that it measures something real.
