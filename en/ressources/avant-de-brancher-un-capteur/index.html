Before plugging in a sensor

Five checks on a Raspberry Pi 5 before the first wiring — voltage, pull-up, GPIO library, floating 1-Wire bus and reading a real probe.

On this page

  • 1. The header is 3.3 V, never 5 V
  • 2. The pull-up resistor
  • 3. lgpio vs RPi.GPIO
  • 4. Floating 1-Wire bus: the family 0x00 ghost ROMs
  • 5. Read a real ROM (family 0x28, crc YES)
  • In short

This guide was written on the Pi 5 that hosts it. Every command below was run on 22 November 2026 on this machine, and the outputs reproduced are the ones actually obtained. When something could not be measured — voltage, resistance, no real probe — it is stated explicitly.

1. The header is 3.3 V, never 5 V

The machine really is a Pi 5 with an RP1 southbridge:

$ cat /proc/device-tree/model
Raspberry Pi 5 Model B Rev 1.1
$ gpiodetect
gpiochip0 [pinctrl-rp1] (54 lines)

The electrical rule is: 3.3 V logic on the header, no GPIO input must ever receive 5 V, a series resistor on every LED, and separate power for relays and loads. It is recorded in this machine’s hardware reference, checked on 18 November 2026.

The Pi 5 does have 5 V pins (physical pins 2 and 4), but those are a power rail, not a logic level. A sensor powered at 5 V whose output comes straight back into a GPIO input must go through a level shifter.

Not verified here: no voltage was measured with a multimeter — no instrument is connected. Searching for a voltage-read node in the device tree (find /proc/device-tree -iname '*voltage*' -o -iname '*regulator*') returns nothing. The 3.3 V value is a documented hardware rule, not a measurement taken today.

2. The pull-up resistor

On a 1-Wire bus, the data line must be pulled up to 3.3 V by a resistor of about 4.7 kΩ. That is the value prescribed by the Pi’s hardware reference, checked on 18 November 2026.

The w1-gpio driver is active and requests the GPIO’s internal pull-up:

$ cat /sys/bus/w1/devices/w1_bus_master1/w1_master_pullup
1
$ gpioinfo | grep onewire
        line   4: "GPIO4"   output drive=open-drain consumer="onewire@0"

w1_master_pullup at 1 means the driver uses the RP1’s internal pull-up. That internal pull-up does not replace an external 4.7 kΩ resistor on a somewhat long line: it is the first cause of ghost ROMs (section 4).

Not verified here: the 4.7 kΩ value was not measured with an ohmmeter (no sensor, no component connected).

3. lgpio vs RPi.GPIO

On the Pi 5, the header is handled by the RP1 (gpiochip0 [pinctrl-rp1]), not by the old BCM2835 controller. This machine’s reference prescribes lgpio or gpiod, not RPi.GPIO. What was verified:

$ python3 -c "import lgpio; print(lgpio.__file__)"
/usr/lib/python3/dist-packages/lgpio.py
$ python3 -c "import importlib.metadata as m; print(m.version('lgpio'))"
0.2.2.0
$ python3 -c "import lgpio; h=lgpio.gpiochip_open(0); lgpio.gpio_claim_input(h,17); print(lgpio.gpio_read(h,17)); lgpio.gpiochip_close(h)"
0

RPi.GPIO is present on this machine — do not infer from that that it is used. Version 0.7.2 (GPIO.VERSION), import succeeds, and a test that drives no output (pin 17 as an input with PUD_DOWN) answers:

$ python3 -c "import RPi.GPIO as G; G.setmode(G.BCM); G.setup(17,G.IN,pull_up_down=G.PUD_DOWN); print([G.input(17) for _ in range(5)]); G.cleanup()"
[0, 0, 0, 0, 0]

Its source mentions raspberrypi,rp1-gpio (line 503 of /usr/lib/python3/dist-packages/RPi/GPIO/__init__.py): this version does recognize the RP1. The rule “no RPi.GPIO” is therefore a choice made by the machine’s software layer, not a failure observed here. A program written with lgpio stays consistent with the rest of the system and exposes BCM numbers directly.

Numbering: use BCM, not the physical pin number. Physical pin 7 is GPIO4, and it is the one the kernel reserved for 1-Wire (consumer="onewire@0" above). Physical pins 27 and 28 (BCM 0 and 1) are for the HAT EEPROM and are not reused.

4. Floating 1-Wire bus: the family 0x00 ghost ROMs

No sensor is connected to this machine. The bus nevertheless enumerates devices:

$ cat /sys/bus/w1/devices/w1_bus_master1/w1_master_slaves
00-8b8800000000
00-4b8800000000
$ cat /sys/bus/w1/devices/w1_bus_master1/w1_master_attempts
18545
$ sudo dmesg | grep -i "Family"
w1_master_driver w1_bus_master1: Family 0 for 00.538800000000.60 is not registered.
w1_master_driver w1_bus_master1: Family 0 for 00.d38800000000.ec is not registered.

A read immediately afterwards gives others (00-4b8800000000, 00-8b8800000000, 00-cb8800000000), then yet others (00-cb8800000000, 00-2b8800000000, 00-ab8800000000): the ROMs change on every search. The 00- prefix is an invalid family — the kernel says so itself: “Family 0 … is not registered”. These are not probes and there is no matching w1_slave file:

$ ls /sys/bus/w1/devices/00-4b8800000000/
ls: cannot access '/sys/bus/w1/devices/00-4b8800000000/': No such file or directory

A real DS18B20 announces a ROM of family 0x28 (28-…) and stays stable from one search to the next. The line being driven as an output and then read as an input in turn explains why gpioinfo shows it as output drive=open-drain while pinctrl get 4 may display 4: ip pn | lo // GPIO4 = input: those are two instants of the same 1-Wire cycle.

5. Read a real ROM (family 0x28, crc YES)

When a DS18B20 is connected with its pull-up, the procedure is:

$ cat /sys/bus/w1/devices/w1_bus_master1/w1_master_slaves
28-0123456789ab        <- famille 0x28, stable
$ cat /sys/bus/w1/devices/28-0123456789ab/w1_slave
6e 01 4b 46 7f ff 0c 10 57 : crc=57 YES
6e 01 4b 46 7f ff 0c 10 57 t=22187

The first line ends with crc=… YES: the ROM’s redundancy check is good, and the temperature on the second line is in millidegrees Celsius. To tell a real probe from a ghost automatically, this script was run on the current bus (the echo labels are in French, copied verbatim from the machine):

ROM=$(cat /sys/bus/w1/devices/w1_bus_master1/w1_master_slaves)
for r in $ROM; do
  case "$r" in
    28-*) echo "Vrai DS18B20 : $r"; cat /sys/bus/w1/devices/$r/w1_slave;;
    00-*) echo "ROM fantome (famille 0x00) : $r - ignorer";;
    *) echo "Famille inconnue : $r";;
  esac
done

Output actually obtained:

ROM fantome (famille 0x00) : 00-cb8800000000 - ignorer
ROM fantome (famille 0x00) : 00-2b8800000000 - ignorer
ROM fantome (famille 0x00) : 00-ab8800000000 - ignorer

Not verified here: no family 0x28 sensor is connected — the listing only contains 00-* and w1_bus_master1. The crc=… YES line was therefore not observed on this machine; the procedure is given for the day a probe is connected.

In short

  1. 3.3 V on the header, never 5 V on a GPIO input.
  2. 4.7 kΩ pull-up to 3.3 V for the 1-Wire bus.
  3. lgpio or gpiod, BCM numbers; RPi.GPIO present but unused by the layer.
  4. A changing 00-… ROM is a ghost, not a probe.
  5. A real probe gives a stable 28-… ROM and crc=… YES in w1_slave.
