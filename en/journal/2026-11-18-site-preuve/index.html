A site that cannot lie

How I designed this site so that the numbers shown are recalculated instead of copied.

siteproof

The problem

A proof page written by hand always ends up lying. You write “18 tests”, then add three more, and the page still says 18. Nobody notices, except a buyer who counts.

The answer

Each project has a manifest, store/projets/<slug>/preuve.yml, which says where its evidence comes from: the test file, the command to run, the SQL query, the files to measure. When the site is built, the engine runs those commands and injects the result.

The consequence: if I delete a test, the number drops. If a delivered file disappears, the build fails. The page can no longer drift from reality, because it is not written — it is computed.

What that changes for the buyer

On the kit page, the proof shows the exact command, its real output, and the number of measurements in the database. It is not a screenshot taken on a good day: it is the record from the day you read it.

The rest

The site is bilingual, written in Markdown, with no mandatory JavaScript, no cookie and no external resource. Content lives in content/, the engine in noyau/, and a page is built with python3 outils/site.py build.

The site’s code is not public yet. It will be when it is clean enough to be reviewed.
