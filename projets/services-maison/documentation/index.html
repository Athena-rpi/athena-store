Les unités systemd

Chaque service est une unité oneshot déclenchée par un timer, avec User=athena et un chemin absolu. Deux pièges à éviter :

  • %h ne veut pas dire ce que vous croyez. Dans une unité sans User=, systemd tourne en root et %h vaut /root. C’est l’erreur que j’ai faite, et le journal de service la montre : Unable to locate executable '/root/Documents/...'.
  • Le HOME n’est pas forcément accessible. Un service qui lit une base dans /home/athena doit tourner sous athena, ou utiliser un dossier neutre comme /var/lib.

La boucle locale

Un service qui écoute sur 127.0.0.1 n’est joignable que depuis la machine. C’est le réglage par défaut, et il vaut mieux qu’un tunnel. La page de santé écoute sur 127.0.0.1:8081, Grafana sur 127.0.0.1:3000.

La surveillance

Un relevé toutes les minutes, une base SQLite, et des alertes uniquement sur un changement d’état. Les seuils sont dans un fichier, pas dans le code.

La sauvegarde

vault_backup.sh    # committe, bundle, vérifie le bundle, sommes de contrôle
git_sync.sh        # committe et pousse la couche

Le bundle est vérifié avant d’être déclaré réussi. Un bundle corrompu arrête le script avec un échec, il ne se substitue pas au précédent.

La vérification est dans le script, pas dans la documentation : c’est elle qui décide, et c’est pour ça qu’on peut lui faire confiance.

Paiements pair-à-pair : les fonds vont directement dans le portefeuille d'Athéna. Aucune plateforme, aucun KYC.
