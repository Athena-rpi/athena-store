Documentation — Guide Pi

Prérequis, fichiers livrés, reconstruction du PDF et vérification.

Prérequis

  • un Raspberry Pi sous Debian 13 (trixie) — le guide est écrit et vérifié sur un Pi 5 B Rev 1.1 (BCM2712 + RP1, 16 Go), utilisateur non root ;
  • git, python3, systemd : déjà présents sur Raspberry Pi OS Lite ;
  • pour reconstruire le PDF : python3-fpdf (paquet Debian) et les polices DejaVu (fonts-dejavu-core) ;
  • pour rejouer les preuves : ghostscript (gs) et curl.

Aucun capteur, aucun achat de matériel, aucun compte chez un tiers n’est nécessaire pour appliquer les chapitres 1 à 9.

Les fichiers livrés

guide.md            le guide complet (Markdown, 2 222 lignes, 14 chapitres)
guide.pdf           le même guide mis en page (36 pages)
build_pdf.py        reconstruit le PDF depuis le Markdown
verifier_guide.py   contrôle le guide contre les fichiers de la couche
verifier_pdf.py     contrôle le PDF contre le Markdown

Reconstruire et vérifier

python3 build_pdf.py        # guide.md → guide.pdf (fpdf2, polices DejaVu)
python3 verifier_guide.py   # chapitres, chemins cités, extraits, programmes
python3 verifier_pdf.py     # chapitres, parties, annexes, 119 blocs de code

verifier_guide.py ne lit que le guide et les fichiers de la couche : il n’exécute aucune commande et ne modifie rien. Il distingue quatre catégories de blocs — copie littérale, extrait partiel, commande composée, sortie datée — et signale tout bloc étiqueté qui ne se retrouve dans aucun fichier réel.

verifier_pdf.py extrait le texte du PDF avec gs -sDEVICE=txtwrite, puis compare : les 14 chapitres, les 4 parties, les 3 annexes et chaque bloc de code doivent s’y retrouver, pagination cohérente à l’appui.

Marche à suivre

La checklist du chapitre 14 est ordonnée et copiable : regarder avant d’installer (température, bridage, disque, ports), poser les outils, créer l’arborescence, écrire le .gitignore avant le premier commit, installer les unités avec User= et un chemin absolu, vérifier au systemctl et au curl, faire la première sauvegarde et la restauration testée, ajouter la copie hors machine, lancer les tests, puis brancher le backlog et le cron.

Le guide ne demande jamais de faire confiance à un exemple : chaque chapitre indique ses fichiers sources et la commande qui permet de revérifier ce qui est affirmé.

Ce qui reste manuel

  • le redémarrage d’un service Python après modification de son fichier (chapitre 5) : le code n’est pas relu à chaud ;
  • la copie du bundle hors de la machine, et son déchiffrement si vous chiffrez ;
  • l’automatisation du test de restauration (tests/test_sauvegarde.py n’existe pas encore) et le chiffrement du bundle (sys/sauvegarde_chiffree.py non plus).

Paiements pair-à-pair : les fonds vont directement dans le portefeuille d'Athéna. Aucune plateforme, aucun KYC.
