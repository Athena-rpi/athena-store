La validation quotidienne, ou ce qu'un script vérifie à 07:20

Ce que sys/validation_quotidienne.py relit chaque matin, ce qu'il remplace, et ce qu'une vérification de présence ne peut pas garantir — chiffres tirés du rapport du 24 novembre.

validationsauvegardemodeles

Le geste

sys/validation_quotidienne.py tourne seul, sans modèle de langage, chaque matin vers 07:20. Il ne « pense » pas : il lit des fichiers, appelle deux commandes git, interroge le catalogue du routeur de modèles, écrit deux fichiers et rend 0 si tout va bien, 1 sinon. Le rapport du 24 novembre porte l’en-tête Athéna — validation quotidienne du 2026-11-24 07:20.

Deux fichiers en sortie : data/validation_quotidienne.txt (relisible) et data/validation_quotidienne.json (lisible par machine). La page de statut sur 127.0.0.1:8081 relit ce JSON — health_web.py y va chercher la dernière validation, il ne la recalcule pas. Le jeton d’accès sert uniquement dans l’en-tête Authorization des requêtes : relu ligne à ligne, le script ne l’affiche nulle part.

Ce qu’elle vérifie

La sauvegarde. Cinq points, plus un sixième ajouté quand l’étude de marché a été ouverte :

  • state/vault.bundle existe et git bundle verify rend le code 0 — le 24, le bundle était âgé de 0,4 h ;
  • des bundles datés backups/vault-*.bundle existent : 208, le plus récent à 0,4 h (seuil : 25 h, AGE_MAX_H = 25.0) ;
  • la couche a un commit récent (0,4 h le 24) et une poussée tracée dans logs/git_sync.log (poussé cecac92) ;
  • le vault est propre : aucun fichier non committé ;
  • etude/RAPPORT.md existe et n’a pas plus de 7 jours (0,5 h le 24).

Le modèle. Le catalogue du routeur est lisible (410 modèles le 24). Le modèle par défaut, meituan/longcat-2.5:free, est présent, gratuit, à 1 048 576 jetons de contexte — et surtout il répond à une sonde réelle : une requête Réponds par OK. limitée à 5 jetons. Les fallbacks sont également cherchés dans le catalogue, pas seulement cités dans la configuration.

Si le modèle par défaut disparaît du catalogue ou ne répond pas, le script choisit un remplaçant : gratuit, apte aux outils, au moins 200 000 jetons de contexte (CONTEXTE_MIN = 200_000), le plus grand contexte disponible, avec une liste de préférences en cas d’égalité. Il sonde le remplaçant avant de l’écrire, puis applique hermes config set model.default. Un rattrapage a été exercé le 19 novembre avec un modèle injouable (compte rendu dans data/recherches/u19-transcript-reel.jsonl) ; non rejoué ce jour.

Le 24, ok = true et changement = false : rien n’a été modifié.

Ce qu’elle remplace

Elle remplace le réflexe « est-ce que j’ai sauvegardé ? est-ce que mon modèle est encore là ? », c’est-à-dire une vérification à la mémoire et à l’occasion, souvent faite seulement après une panne. Le contrôle passe du souvenir à une liste écrite, exécutée au même moment chaque jour, avec une trace datée.

Elle remplace aussi le test « le modèle est dans le catalogue, donc il marche » par « le modèle est dans le catalogue et il a répondu à une requête ». C’est la différence entre une fiche et une sonde.

Elle ne remplace pas la relecture de Jacob avant diffusion : le site n’est pas publié par ce script, et rien ici n’autorise une publication.

Ce qu’elle ne peut pas garantir

  • git bundle verify n’est pas une restauration. Il prouve qu’un bundle est lisible et forme une histoire complète du point de vue de git. Aucune restauration n’est faite dans un dossier vide ; la capacité à rebâtir la machine depuis le bundle n’est donc pas vérifiée.
  • Les seuils sont des conventions, pas des mesures de risque. 25 heures pour un bundle, 7 jours pour un rapport : une dérive lente à l’intérieur de la fenêtre passe. Un fichier trop vieux est signalé, il n’est pas réparé.
  • La sonde est minimale. Une phrase, 5 jetons : elle établit qu’une réponse est revenue, pas qu’elle est bonne, pas qu’un agent peut s’en servir pour un vrai travail avec outils, pas que le modèle restera disponible le reste de la journée. Le cas « présent au catalogue mais muet » n’a pas pu être reproduit lors de la mise en place : non vérifié.
  • Elle dépend du réseau et d’un jeton. Si le catalogue est illisible, le script écrit « catalogue illisible (jeton ou réseau) — non vérifié » et rend 1. Il constate, il ne rétablit ni le réseau ni le jeton.
  • Le choix du remplaçant est une heuristique. Gratuit + outils + grand contexte n’est pas un classement de qualité ; personne n’a mesuré le coût d’une tâche réelle avec chaque candidat.
  • Le rapport reflète la configuration, sans la juger. Le 24, le même fallback tencent/hy4-flash:free apparaît deux fois dans le JSON : le script itère sur les entrées lues, il ne déduplique pas.
  • Le script n’envoie aucun message. Aucun appel à signal_send dans le code (vérifié par recherche) : il imprime, écrit ses deux fichiers et rend 0 ou 1. Une alerte éventuelle est portée par la couche autour, pas par lui.
  • Son périmètre s’arrête là. Il ne surveille ni les portefeuilles, ni les secrets, ni la température, ni le GPIO, ni les cron, ni la publication du site.

Relu sur la machine
