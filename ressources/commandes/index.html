Arsenal de vérification — les commandes du Pi, ce qu'elles prouvent

Référence des commandes réellement exécutées sur ce Pi 5, découpée en fiches — chaque fiche donne la commande, ce qu'elle vérifie et le piège qu'elle évite. Sorties relevées le 22 novembre 2026.

Cette page recense les commandes réellement utilisées sur ce Raspberry Pi 5 par la couche Athéna, les manifestes de preuve et les vérifications quotidiennes. Chacune a été exécutée le 22 novembre 2026 sur la machine qui héberge le site ; les sorties reproduites sont celles obtenues, sans correction.

Le contenu est découpé en 19 fiches, une par commande (F01 à F19). Chaque fiche répond à trois questions : la commande lancée, ce qu’elle vérifie, le piège qu’elle évite. Les fiches sont regroupées par thème ; la numérotation est stable et sert d’ancre.

Elle complète Avant de brancher un capteur (électricité et bus) et Format du manifeste de preuve (comment une commande devient une preuve). Ici, c’est l’arsenal lui-même qui est décrit.

1. L’identité, pas l’architecture seule

F01 — tr -d '\0'

$ tr -d '\0' </proc/device-tree/model
Raspberry Pi 5 Model B Rev 1.1

Vérifie : le modèle exact de la carte, révision 1.1.

Piège évité : /proc/cpuinfo donne le processeur (BCM2712) mais pas la révision de la carte. cat /proc/device-tree/model se termine par un octet NUL sans retour à la ligne et colle le prompt ; tr -d '\0' produit une ligne propre.

F02 — uname -srm

$ uname -srm
Linux 6.18.50+rpt-rpi-2712 aarch64

Vérifie : le noyau et l’architecture arm64.

Piège évité : uname -m seul donne aarch64 et ne dit rien du noyau ; le suffixe +rpt-rpi-2712 confirme un noyau Raspberry Pi.

F03 — python3 --version

$ python3 --version
Python 3.13.5

Vérifie : l’interpréteur qui exécute les scripts de preuve.

Piège évité : python --version peut désigner un autre interpréteur — les manifestes utilisent explicitement python3.

2. GPIO : le bon contrôleur, le bon numéro

F04 — gpiodetect

$ gpiodetect
gpiochip0 [pinctrl-rp1] (54 lines)
gpiochip10 [gpio-brcmstb@107d508500] (32 lines)
gpiochip11 [gpio-brcmstb@107d517c00] (15 lines)
gpiochip12 [gpio-brcmstb@107d517c20] (6 lines)
gpiochip13 [gpio-brcmstb@107d508520] (4 lines)

Vérifie : le header est gpiochip0, pilote pinctrl-rp1 — la southbridge RP1 du Pi 5.

Piège évité : gpiodetect renvoie aussi quatre chips BRCMSTB ; l’erreur serait de prendre « le premier » ou gpiochip10. RPi.GPIO est importable sur cette machine, mais la couche utilise lgpio/gpiod et les numéros BCM.

F05 — gpioinfo | grep onewire

$ gpioinfo | grep onewire
        line   4: "GPIO4"   output drive=open-drain consumer="onewire@0"

Vérifie : BCM4 est réservé au bus 1-Wire.

Piège évité : la ligne apparaît en output parce qu’elle est pilotée en sortie à cet instant du cycle 1-Wire ; pinctrl get 4 peut afficher input une microseconde plus tard. Ce n’est pas un conflit. La broche physique 7 est BCM4 : on raisonne en BCM, jamais en numéro de broche.

3. Chaleur et throttling

F06 — vcgencmd measure_temp && vcgencmd get_throttled

$ vcgencmd measure_temp && vcgencmd get_throttled
temp=42.8'C
throttled=0x0

Vérifie : température du SoC et état d’alimentation/thermique.

Piège évité : lire seulement la température. throttled=0x0 est la preuve qu’aucun throttling n’est actif ni survenu ; un code non nul se décompose en bits courants et passés. Le && garantit que les deux relevés viennent du même instant ; avec ; ils pourraient être séparés. Repère de throttling thermique : environ 80 °C — 42,8 °C relevés ici.

4. Bus et capteurs

F07 — ls /dev/i2c-* /dev/spidev* 2>/dev/null

$ ls /dev/i2c-* /dev/spidev* 2>/dev/null
/dev/spidev0.0
/dev/spidev0.1
(code de retour 2)

Vérifie : deux périphériques SPI présents, aucun périphérique I2C (i2c_arm=on dans la config mais le module i2c-dev n’est pas chargé au boot, donc pas de /dev/i2c-1).

Piège évité : 2>/dev/null cache le message d’erreur mais le code 2 reste — c’est une preuve d’absence, pas une panne de la commande. Ajouter || true transformerait cette absence en succès : à proscrire dans un manifeste.

F08 — cat /sys/bus/w1/devices/w1_bus_master1/w1_master_slaves

$ cat /sys/bus/w1/devices/w1_bus_master1/w1_master_slaves
00-666800000000
00-e66800000000

Vérifie : le bus 1-Wire énumère deux ROMs de famille 0x00.

Piège évité : ces ROMs changent à chaque lecture et n’ont pas de fichier w1_slave — ce sont des fantômes d’un bus flottant, pas des sondes. Une vraie sonde donne une ROM 28-… stable et crc=… YES dans w1_slave. La liste relevée ici diffère de celle du guide : attendu sur un bus sans capteur.

5. Services et minuteurs

F09 — systemctl --failed --no-pager

$ systemctl --failed --no-pager
  UNIT LOAD ACTIVE SUB DESCRIPTION

0 loaded units listed.

Vérifie : aucune unité systemd en échec.

Piège évité : --no-pager est indispensable en cron, sinon le pager attend une touche. --failed ne remplace pas is-active : une unité simplement inactive n’est pas en échec.

F10 — systemctl list-timers 'athena-*' --no-pager

$ systemctl list-timers 'athena-*' --no-pager
NEXT                            LEFT LAST                              PASSED UNIT
Sun 2026-11-22 19:49:48 EST      30s Sun 2026-11-22 19:48:48 EST      29s ago athena-health.timer
Sun 2026-11-22 19:50:33 EST 1min 15s Sun 2026-11-22 17:50:33 EST 1h 58min ago athena-git-sync.timer
Sun 2026-11-22 19:51:00 EST 1min 42s Sun 2026-11-22 19:48:01 EST 1min 15s ago athena-flux.timer
Sun 2026-11-22 19:54:33 EST     5min Sun 2026-11-22 19:39:33 EST      9min ago athena-gardien.timer
Mon 2026-11-23 03:17:00 EST       7h Sun 2026-11-22 03:17:11 EST      16h ago athena-vault-backup.timer
(extrait — 7 minuteurs au total, code de retour 0 sans tube)

Vérifie : sept minuteurs athena-* chargés et leur prochaine exécution.

Piège évité : relevé ce jour, systemctl list-timers … | head -8 donne un code 141 (SIGPIPE) alors que les minuteurs vont bien. Un head ne doit jamais fournir le verdict d’une preuve : on tronque la sortie après coup, pas le tube.

F11 — systemctl is-active …

$ systemctl is-active athena-health.timer athena-health-web.service athena-vault-backup.timer athena-git-sync.timer
active
active
active
active

Vérifie : les quatre unités interrogées sont actives au moment du relevé.

Piège évité : is-active décrit l’état courant, is-enabled le démarrage au boot. Un code 3 signifie « inactif », ce n’est pas une erreur système.

6. Réseau local

F12 — ss -ltnp | grep -E ':8080|:8081'

$ ss -ltnp | grep -E ':8080|:8081'
LISTEN 0  5  127.0.0.1:8081  0.0.0.0:*  users:(("python3",pid=240333,fd=3))
LISTEN 0  50 [::ffff:127.0.0.1]:8080  *:* users:(("signal-cli",pid=1157,fd=16))

Vérifie : les ports d’écoute et leurs processus, tous deux sur loopback.

Piège évité : un port ouvert ne prouve pas une réponse HTTP ; on le complète par la fiche F13. -p n’affiche le PID que si l’utilisateur en a le droit.

F13 — curl -s -o /dev/null -w '%{http_code}\n' 127.0.0.1:8081/

$ curl -s -o /dev/null -w '%{http_code}\n' 127.0.0.1:8081/
200

Vérifie : la page d’accueil locale répond.

Piège évité : -s et -o /dev/null masquent le corps et les messages d’erreur ; un 200 seul ne prouve pas le contenu, seulement la réponse. Sur ce Pi l’IPv6 était cassé (double pile ~24 s) ; /etc/gai.conf met precedence ::ffff:0:0/96 100 pour préférer IPv4. Ailleurs, forcer curl -4.

7. Santé et données

F14 — python3 sys/health_status.py

$ python3 sys/health_status.py
Dernier échantillon : 2026-11-22T19:48:48-05:00
  température   42.8 °C   (24 h : min 38.9 / moy 41.84 / max 62.6)
  throttled    0x0
  tension cœur  0.7638 V
  uptime        76.2 h   charge 0.21
  disque        16.6 %   (24 h max 16.6 %)
  unités en échec 0   wlan -64.0 dBm   ntp oui
  échantillons 24 h : 1370   événements throttle : 0

Vérifie : lecture consolidée de data/health.db, des unités systemd, de la température et du réseau.

Piège évité : le script lit la base, il ne la réécrit pas. Les alertes qu’il affiche en fin de sortie sont historiques (18 et 21 novembre) : ne pas les confondre avec l’état courant, qui est 0 unité en échec.

F15 — select count(*) from samples

select count(*) from samples

Vérifie : le nombre d’échantillons enregistrés, délégué à la base et non écrit à la main.

Piège évité : le moteur ouvre la base en URI file:…?mode=ro — lecture seule, le manifeste ne peut pas modifier ce qu’il mesure. count(*) renvoie 0 sur une table vide ; ce n’est pas la même chose qu’une base absente.

8. Git et sauvegarde

F16 — git bundle verify state/vault.bundle

$ git bundle verify state/vault.bundle
The bundle contains these 2 refs:
360336371e5fc79e55bbf95cb517f4f7d82fdad0 refs/heads/main
360336371e5fc79e55bbf95cb517f4f7d82fdad0 HEAD
The bundle records a complete history.
The bundle uses this hash algorithm: sha1

Vérifie : le bundle du vault est lisible, complet et couvre l’historique.

Piège évité : verify ne prouve pas que le dépôt se restaure réellement. La preuve du guide enchaîne git clone du bundle, git fsck --full et sha256sum d’un fichier connu.

F17 — git ls-files | grep -E 'secrets/|\.env|\.seed'

$ git ls-files | grep -E 'secrets/|\.env|\.seed' || echo 'aucun secret versionné'
aucun secret versionné

Vérifie : aucun fichier sensible n’est dans l’index git.

Piège évité : sans le || echo, grep renvoie le code 1 quand rien ne correspond (relevé : rc=1) — un « échec » qui est une bonne nouvelle. Le contenu d’un secret ne doit jamais être affiché, seulement son absence constatée.

F18 — git log -1 --format='%h %ad %s' --date=short

$ git log -1 --format='%h %ad %s' --date=short
3d945a3 2026-11-22 sauvegarde auto 2026-11-22 18:55

Vérifie : dernier commit, sa date courte et son objet.

Piège évité : sans --date=short, %ad produit une date verbeuse et dépendante de la locale, donc non reproductible d’une machine à l’autre.

9. Backlog

F19 — python3 sys/backlog.py etat

$ python3 sys/backlog.py etat
backlog : 129 tâches — {'fait': 42, 'bloqué': 3, 'prêt': 84}
reste : 2495 min (41.6 h)
prochaine : T30 — Référentiel de commandes

Vérifie : l’état réel lu dans state/backlog/taches.json, et la tâche suivante renvoyée par python3 sys/backlog.py suivante (ici T30).

Piège évité : etat donne les compteurs, suivante donne la tâche à exécuter. Une tâche bloquée n’est pas une tâche faite. Ne pas recalculer le plan à la main : state/plan.md est régénéré depuis le JSON par script.

10. Règles d’écriture — les six pièges récapitulés

  1. Ne jamais corriger un échec avec || true : le verdict « OK » perd tout sens.
  2. 2>/dev/null masque le message, pas le code de retour : laissez le code apparaître.
  3. Ne pas faire d’un | head une preuve : SIGPIPE 141 n’est pas une panne du service.
  4. Sur Pi 5, RPi.GPIO s’importe mais la couche utilise lgpio/gpiod ;gpiodetect liste cinq chips, le header est gpiochip0.
  5. Raisonner en BCM, pas en numéro de broche physique.
  6. Ne pas echo un chiffre : déléguer la mesure à une commande ou à un compteur SQL en mode=ro.

Le détail du contrat est dans Format du manifeste de preuve.

Limites

Aucune mesure de tension au multimètre ni de résistance à l’ohmmètre n’a été faite : aucun instrument n’est branché. Aucune sonde de famille 0x28 n’est connectée : la ligne crc=… YES n’a pas été observée ici. Les sorties ci-dessus sont un instantané du 22 novembre 2026 : ROMs 1-Wire, température, compteurs et PID changent d’une exécution à l’autre. Une commande vérifiée ici ne garantit pas qu’elle donnera la même valeur demain — seulement qu’elle mesure quelque chose de réel.

Paiements pair-à-pair : les fonds vont directement dans le portefeuille d'Athéna. Aucune plateforme, aucun KYC.
